# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-02-14
**Phases:** 1-3
**Total Plans:** 8

## Overview

Initial MVP release of Opendots — a public community website to publish, discover, and download OpenCode configuration "bundles" (dotfiles). Publishers connect via GitHub OAuth and register a repo they control; Opendots imports it, validates it, and presents a great bundle page with previews, safety signals, and downloads.

## Phases

### Phase 1: Publisher Import Pipeline

**Goal**: Publishers can authenticate and publish bundles via a validated GitHub repo import that produces stable snapshot data.
**Depends on**: Nothing (first phase)
**Plans**: 3 plans

Plans:

- [x] 01-01: Auth + session persistence (GitHub OAuth) — Wave 1
- [x] 01-02: Repo registration + manifest/naming validation — Wave 2
- [x] 01-03: Import + snapshot + manual refresh + import metadata — Wave 3

**Details:**
- Created Fastify backend with Better Auth GitHub OAuth integration
- Implemented cookie-based session management with SQLite persistence
- Built GitHub API client with Octokit for repo verification and manifest fetching
- Created manifest validation using Zod schema (opendots.yml/json)
- Implemented import pipeline that downloads repo snapshots via GitHub API
- Added concurrent refresh protection (409 conflict)

### Phase 2: Great Bundle Pages + Safety + Downloads

**Goal**: Visitors can understand bundle contents, see safety signals, and download/install the bundle in supported layouts.
**Depends on**: Phase 1
**Plans**: 3 plans

Plans:

- [x] 02-01: Bundle detail page (file tree, previews, metadata, repo link) — Wave 1
- [x] 02-02: Import-time validation + risk scanning + secret scanning — Wave 1
- [x] 02-03: Safety display + ZIP downloads + install instructions + docs page — Wave 2

**Details:**
- Created public bundle API endpoints (GET /api/bundles, /api/bundles/:id, /api/bundles/:id/file)
- Implemented file index extraction from snapshot zips with lazy-loaded syntax-highlighted previews
- Added schema validation for opencode.json/jsonc, theme JSON, SKILL.md frontmatter
- Built risk flag detection (EXEC, SHELL, REMOTE, EVAL) and best-effort secret scanning
- Created streaming ZIP generator with project/global layout variants
- Built safety display with risk badges and user responsibility disclaimer
- Wrote comprehensive Docs page covering bundles, install destinations, and safety model

### Key Decisions

- Decision: Use Better Auth instead of NextAuth/Clerk — simpler setup, built-in Drizzle adapter, no vendor lock-in
- Decision: Use Fastify instead of Express — better TypeScript support, plugin architecture
- Decision: Cookie-based sessions — simpler SPA integration with automatic HTTP-only cookie management
- Decision: Vite dev proxy for /api — eliminates CORS complexity in development
- Decision: Desktop-only v1 — reduce UX scope while shipping great bundle pages
- Decision: Manual refresh only in v1 — reduce complexity (no webhooks)
- Decision: Allow plugins/tools/! but scan + warn — user responsibility, but portal surfaces risk
