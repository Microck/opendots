<task type="auto">
  <name>Task 2: Implement repo registration endpoint with naming + manifest validation</name>
  <files>backend/src/routes/publisherBundles.ts, backend/src/github/githubClient.ts, backend/src/import/manifest.ts</files>
  <action>
Implement authenticated bundle endpoints:
- `POST /api/publisher/bundles` accepting `{ repo: "owner/opendots-<slug>" }` or a GitHub repo URL.
- `GET /api/publisher/bundles` returning the signed-in publisher's registered bundles.

Validation requirements:
- Enforce repo name regex: `^opendots-[a-z0-9]+(-[a-z0-9]+)*$`.
- Verify the signed-in publisher "controls" the repo using GitHub API permissions (require `admin` OR `maintain`).
- Fetch `opendots.yml` from repo root and parse YAML.
- Validate manifest with Zod (minimal required fields): `id`, `name`, `summary`, `license`; allow unknown keys.

Error handling requirements (for clear UI messaging):
- Return 400 with `{ code, message, field? }` for validation errors (bad repo string, bad name, missing/invalid manifest).
- Return 403 for "no control" permission.
- Return 404 for repo not found (or not accessible).

Implementation notes:
- Create an Octokit client configured with throttling.
- Use the Better Auth session context to access the GitHub access token (server-side only). Do not expose tokens to the browser.
  </action>
  <verify>
`npm --prefix backend run lint && npm --prefix backend run build`

With server running and signed out:
- `curl -i http://localhost:8787/api/publisher/bundles` (expect 401 for GET)

With server running and signed in (reuse your browser session cookie; e.g. copy the `Cookie:` header from DevTools for `http://localhost:8787`):

- 400 invalid repo string (field-level validation, no GitHub call):
  - `curl -sS -i -X POST http://localhost:8787/api/publisher/bundles -H 'content-type: application/json' -H 'cookie: <PASTE_COOKIE>' -d '{"repo":"not a repo"}'`
  - Expect: `HTTP/1.1 400` and JSON payload containing `{ "code": string, "message": string, "field": "repo" }`.

- 400 invalid repo name (repo must match `opendots-<slug>`):
  - `curl -sS -i -X POST http://localhost:8787/api/publisher/bundles -H 'content-type: application/json' -H 'cookie: <PASTE_COOKIE>' -d '{"repo":"owner/hello-world"}'`
  - Expect: `HTTP/1.1 400` and JSON payload containing `{ "code": string, "message": string, "field": "repo" }`.

- 404 repo not found (or not accessible):
  - `curl -sS -i -X POST http://localhost:8787/api/publisher/bundles -H 'content-type: application/json' -H 'cookie: <PASTE_COOKIE>' -d '{"repo":"octocat/opendots-this-does-not-exist-123456"}'`
  - Expect: `HTTP/1.1 404` and JSON payload containing `{ "code": string, "message": string }`.

- 403 no control (use a real existing repo you can read but do not have maintain/admin on):
  - `curl -sS -i -X POST http://localhost:8787/api/publisher/bundles -H 'content-type: application/json' -H 'cookie: <PASTE_COOKIE>' -d '{"repo":"<some-owner>/opendots-<some-slug-you-dont-control>"}'`
  - Expect: `HTTP/1.1 403` and JSON payload containing `{ "code": string, "message": string }`.

- 400 missing/invalid `opendots.yml` (use a repo you control named `opendots-...` but without a valid `opendots.yml` at repo root):
  - `curl -sS -i -X POST http://localhost:8787/api/publisher/bundles -H 'content-type: application/json' -H 'cookie: <PASTE_COOKIE>' -d '{"repo":"<you>/opendots-<slug-without-manifest>"}'`
  - Expect: `HTTP/1.1 400` and JSON payload containing `{ "code": string, "message": string, "field": "manifest" }` (or similar field identifier).

Payload shape spot-check (any of the above 4xx responses):
- `curl -sS -X POST http://localhost:8787/api/publisher/bundles -H 'content-type: application/json' -H 'cookie: <PASTE_COOKIE>' -d '{"repo":"not a repo"}' | node -e 'const j=JSON.parse(require("fs").readFileSync(0,"utf8")); if(!j.code||!j.message) process.exit(1); console.log("ok", {code:j.code, field:j.field});'`
  </verify>
  <done>
- `POST /api/publisher/bundles` rejects invalid repo names and missing/invalid `opendots.yml` with clear error payloads.
- Successful registration creates a DB record tied to the publisher.
- `GET /api/publisher/bundles` returns only the signed-in publisher's bundles.
  </done>
</task>
