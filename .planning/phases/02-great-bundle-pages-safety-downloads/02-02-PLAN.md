  <action>
Create `backend/src/import/validator.ts` that validates OpenCode artifacts found in a snapshot:

1. **Config validation (SAFE-01):** If `opencode.json` or `opencode.jsonc` exists, validate against a bundled JSON schema. Use `ajv` for validation. For JSONC, use `comment-json` to strip comments before validating. Bundle a reasonable config schema locally (fetch from `https://opencode.ai/config.json` once and cache, or embed a minimal known-good schema). If schema fetch fails, skip validation and record a warning.

2. **Theme validation (SAFE-02):** If theme JSON files exist (under `.opencode/themes/` or matching theme patterns), validate against a theme schema. Same approach: embed or cache schema from `https://opencode.ai/theme.json`.

3. **Skill frontmatter validation (SAFE-03):** If `SKILL.md` files exist, parse YAML frontmatter with `gray-matter`. Check required fields: `name`, `description`. Flag missing or empty required fields.

Return a structured validation result:
```ts
interface ValidationResult {
  config: { valid: boolean; errors: string[] } | null
  themes: { file: string; valid: boolean; errors: string[] }[]
  skills: { file: string; valid: boolean; errors: string[] }[]
}
```

Install backend deps: `npm install --prefix backend ajv comment-json gray-matter`

Write a quick unit-style test:

  <files>backend/src/import/riskScanner.ts, backend/src/import/secretScanner.ts, backend/src/import/importer.ts, backend/src/db/schema/imports.ts</files>
  <action>
Create risk flag detector (`backend/src/import/riskScanner.ts`):
- Scan file contents for risk indicators (SAFE-04):
  - `EXEC`: Files containing `exec(`, `spawn(`, `execSync(`, `child_process`, or shebang lines
  - `SHELL`: Files containing shell command patterns (`!` command prefix in OpenCode commands, `.sh` scripts)
  - `REMOTE`: Files containing URLs to external resources (`http://`, `https://`, `ftp://`)
  - `EVAL`: Files containing `eval(`, `Function(`, `new Function`
- Return `riskFlags: { flag: string; files: string[]; severity: 'high' | 'medium' | 'low' }[]`

Create secret scanner (`backend/src/import/secretScanner.ts`):
- Implement a regex-based best-effort secret scanner (SAFE-05):
  - Common patterns: API keys (long hex/base64 strings with key prefixes like `sk_`, `AKIA`, `ghp_`, `glpat-`), private keys (`-----BEGIN.*PRIVATE KEY-----`), connection strings with passwords, AWS access keys.
  - Return `secretWarnings: { file: string; line: number; pattern: string; snippet: string }[]` (redact actual values, show pattern match type only).
- This is explicitly best-effort — label it as such in output.

Integrate into the import pipeline:
- After snapshot zip is created, run validator + riskScanner + secretScanner over the extracted files.
- Add a `safetyResults` text column (JSON) to the snapshots table to persist all results.
- Store the combined output: `{ validation: ValidationResult, riskFlags: RiskFlag[], secretWarnings: SecretWarning[] }`.
- Include safety results in the `GET /api/bundles/:id` response (from Plan 02-01).

Non-goals:
- Do not use `gitleaks` CLI for v1; regex patterns are sufficient for best-effort.
- Do not block import on scan failures — always produce a snapshot, with scan results as metadata.
  </action>

- Should show validation results, risk flags, and secret warnings (or empty arrays if none found).
  </verify>
