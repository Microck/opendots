  <name>Task 1: Add bundle listing API with card-ready fields + accent color extraction</name>
  <files>backend/src/routes/publicBundles.ts, backend/src/db/schema/publisher.ts</files>
  <action>
Extend the public bundles API (created in Phase 2) with a listing endpoint:

`GET /api/bundles` → Returns an array of card-ready bundle objects:
```ts
interface BundleCard {
  id: string
  slug: string
  name: string
  summary: string
  tags: string[]
  artifactTypes: string[]  // e.g. ["themes","commands","skills"]
  riskBadges: string[]     // e.g. ["EXEC","SHELL"]
  accentColor: string | null  // extracted from theme primary color
  stars: number
  forks: number
  updatedAt: string  // ISO datetime (snapshotImportedAt)
}
```

Support query parameters (for Plan 03-02):
- `q` (text search — name/summary/tags), `tag`, `type` (artifact type), `opencode` (compat version), `sort` (default: `newest`)
- For now, implement basic filtering: exact tag match, exact artifact type match, `q` as case-insensitive LIKE on name+summary+tags. Sort by `updatedAt DESC` for `newest`.

Accent color extraction:
- During import (or as a computed field), if the bundle contains a theme JSON with a `colors.primary` or `primary` field, store that hex value as `accentColor` on the bundle record.
- Add an `accentColor` column to the bundles table if not present.
- If no theme or no primary color found, leave as null (frontend handles fallback).

GitHub stats:
- Store `stars` and `forks` from the GitHub API response during registration/refresh. Add columns if not present.
- These are snapshot values (captured at import time), not live-fetched.
  </action>

  </verify>
